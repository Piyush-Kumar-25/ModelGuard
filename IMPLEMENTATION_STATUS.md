# ModelGuard Backend Final — v1.0.1

Updated from `ModelGuard-modelguard-update(1).zip` (SHA-256 `963c5902653021efc667914102a37ad54417a26c77934fa15102477bd71cc843`). The original archives are unchanged. This distribution contains backend source, requirements, test code and documentation only.

## Changes

- Only evaluated incumbents and finalized, approved challengers of the active incumbent can export deployment bundles. Model cards distinguish deployment-eligible and evaluation-only models.
- Byte-identical production batch retries reuse the original batch ID. Previously recorded duplicates are excluded from persistence evidence without deleting them. Repeated important-feature drift requires the same feature across distinct compatible observations.
- Confirmed delayed labels accumulate by stable record ID in a transaction and can coexist with inline labels. Conflicts are rejected without overwriting values. Drift history flags analyses made stale by label or mapping changes.
- Small labelled batches cannot establish that a model remains safe to use. A model-specific report includes only its own experiments and relevant parent/challenger results.

## Intended use and limits

Single-worker local FastAPI/SQLite backend. Streamlit can integrate against the documented API, but is not part of this ZIP. No multi-user auth, distributed jobs or automatic deployment/model replacement. Exact-content deduplication does not prove that differently formatted files are independent. Current legacy label pointers remain readable; resubmit any upload that was previously overwritten if you want its labels merged. Model metrics and synthetic examples are not a production-readiness guarantee. See `backend/README.md` and `REQUIREMENTS_COVERAGE.md` for details.
